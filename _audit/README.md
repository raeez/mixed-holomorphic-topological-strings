## No-downgrade rule (binding)

From the XLSX `Executive_Spine`:

> Anomaly $\Rightarrow$ projective curvature; divergence $\Rightarrow$ admissible topology; action $\Rightarrow$ centrality homotopies; local $\Rightarrow$ stalk of obstruction theorem.

A resolution is admissible only if the stronger object is **retained** in
$\mathcal{B}^{\mathrm{adm}}$ and the reduced statement is reached
**only as the image of an explicit forgetful functor**.  The four
deepest surgical changes are:

1. anomaly $\Rightarrow$ projective curvature;
2. divergent Casimir $\Rightarrow$ Tate/pro-Matlis kernel;
3. action on branes $\Rightarrow$ Hochschild centrality Maurer–Cartan datum;
4. local theorem $\Rightarrow$ formal-Darboux stalk of a global obstruction theorem;
5. curve vertex algebra $\Rightarrow$ restriction shadow of the native surface factorization algebra.

Any patch that *erases* projective curvature, *deletes* the kernel
admissibility datum, *collapses* centrality homotopies to plain action,
or *truncates* the obstruction taxonomy violates the rule.

## The monotone spine (XLSX `Monotone_Spine`)

$$
T_{\mathrm{finite}} \;<\; T_{\mathrm{coord}} \;<\; T_{P_0} \;<\; T_{\mathrm{kernel}} \;<\; T_{\mathrm{bar/cobar}} \;<\; T_{\mathrm{Hoch}} \;<\; T_{\mathrm{Capelli}} \;<\; T_{\mathrm{QME}} \;<\; T_{\mathrm{KN/global}} \;<\; T_{\mathrm{compact}}.
$$

Each level carries a *strong object*, a *forgetful shadow*, and a
*strictness witness*; `audit_loop.py monotone` prints the table.

The audit's `Theorem level` column also contains two cross-cutting
labels that do not appear in the canonical chain:

| label | rank | meaning |
|---|---|---|
| `T_spine` | $0$ | foundational cross-level structural entries (720 rows) |
| `T_adm` | between `T_P_0` and `T_kernel` | admissible-topology infrastructure (156 rows) |
| `T_quant/radial` | between `T_kernel` and `T_bar/cobar` | quantization / radial / PBW data (78 rows) |
| `T_exposition` | $99$ | exposition / references / cross-refs (210 rows) |

The CLI orders open work by `(theorem-level rank, severity rank, page)`,
so `T_spine` foundations resolve first, then the spine builds upward,
and `T_exposition` polishes last.

## Status taxonomy (used by `state.json`)

| status | meaning |
|---|---|
| `actionable` | seed state from the XLSX `Status` column |
| `in_progress` | being addressed in this session |
| `resolved` | upgrade inscribed in `.tex`; verification probe not yet run |
| `verified` | upgrade inscribed *and* the entry's `Verification / consistency probe` has been executed and passed |
| `deferred` | upgrade depends on cross-volume or external input; named obstruction recorded in `notes` |
| `blocked` | depends on another open entry; record the blocker ID in `notes` |

Only `verified` (or a `deferred` carrying a precise named obstruction)
discharges the no-downgrade requirement.  Marking an entry `resolved`
without a verification probe leaves a debt that the next pass collects.

## Resolution loop (the goal-driven contract)

The slash command `/goal resolve all issues on the xls` runs the loop:

```
while open entries remain:
    propose K = scripts/audit_loop.py next --limit K
    for entry in proposed:
        scripts/audit_loop.py show <ID>                   # read the issue + upgrade + probe
        # state the plan in 2-3 sentences before editing
        scripts/audit_loop.py mark <ID> --status in_progress
        # inscribe the strongest-upgrade construction into the relevant .tex file
        # run the named verification probe (compute script, formula check, primary source)
        scripts/audit_loop.py mark <ID> --status verified \
            --commit <hash> --verification "<probe outcome>" --note "<obstruction or pointer>"
    scripts/audit_loop.py progress                         # checkpoint
session end: make release; scripts/audit_loop.py progress
```

Each pass moves *upward* along the monotone spine.  Builds happen at
session end per the repo rule, not per entry.  Stale `pdflatex`
processes are cleared with `pkill -9 -f pdflatex 2>/dev/null; sleep 2`.

## Success criterion (XLSX `Executive_Spine`)

> Every stronger theorem has a named forgetful functor to a weaker
> shadow; every stronger theorem retains data killed by the weaker one.

Operationally:

* every `resolved` entry's `verification` field carries the probe outcome;
* every `deferred` entry's `notes` field names the precise missing
  construction (cohomology class, cokernel functional, Roos class,
  graph row, finite-window matrix equation, primary literature gap);
* `audit_loop.py monotone` shows no `UNRANKED` theorem levels;
* `audit_loop.py progress` shows zero `actionable` entries and zero
  `in_progress` entries at session end.
